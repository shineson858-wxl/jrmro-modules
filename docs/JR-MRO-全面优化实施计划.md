# JR MRO 商城 · 全面优化实施计划

> 依据：《JR MRO 行业实操整改优化建议书》约 60 项建议（P0/P1/P2）
> 目标：让系统真正服务越南北宁 / 北江工业区工厂客户（找货 → 交易 → 结算 → 履约 → 复购闭环）
> 原则：**先上线硬门槛（P0），再深化体验（P1），最后数据与持续迭代（P2）**；每个阶段有明确目标、验收标准与里程碑。

---

## 〇、总体排期（概览）

| 阶段 | 名称 | 内容 | 目标 | 建议项 | 状态 |
|---|---|---|---|---|---|
| **Phase 1** | 上线硬门槛（P0 全部） | 找货/交易/结算/履约/客户/合规 | 能在工业区正式开张 | 约 23 项 P0 | ✅ **已完成**（6 批全部落地+验证） |
| **Phase 2** | 交易体验深化（P1 前半） | 议价/历史价/物流/单据合规/安全 | 提升成交率与留存 | 13 项 P1 | ✅ **已完成**（4 批全部落地+验证） |
| **Phase 3** | 企业化与数据运营（P1 后半 + P2） | 看板/销售分析/多采购员/合同/条码/审批流 | 支撑规模化经营 | 约 15 项 | ✅ **已完成 15/15**（3 批 + F4/J2/上架审核，回归验收通过） |

## 一、执行顺序与依赖关系

```
Phase 1（P0）        必须最先，互相有依赖
   ├─ 先做"找货"（型号/规格/搜索）→ 决定询价报价的对象质量
   ├─ 再做"交易"（批量询价/报价商务件）→ 依赖找货
   ├─ 同步做"结算合规"（发票/企业/对公）→ 独立可并行
   ├─ 再做"履约"（库存/配送）→ 依赖商品与订单
   └─ 最后"上线"（证书/域名/隐私）→ 全部功能就绪后
Phase 2（P1）       在 P0 稳定后逐步加（议价/物流/业务员/报表）
Phase 3（P1+P2）    随客户量增长而加（分层/权限/看板/合同）
Phase 4（P2/延后）  持续迭代（支付/CA/缓存/移动）
```

**关键路径（建议优先投入）**：原厂型号检索 → 规格体系 → 批量询价+商务报价 → 增值税发票 → 对公结算 → 实时库存+配送时效 → 固定域名+证书。

**可并行**：结算合规（D1-D4/G1）、隐私合规（M1）、术语词库（I1）、单据合规（J1）相对独立，可并行开发。

## 三、风险与应对

| 风险 | 应对 |
|---|---|
| 原厂型号/规格数据量巨大，整理成本高 | 先覆盖 Top 20 高频品类，其余逐步补 |
| 越南发票/税务规范复杂 | 请本地财务/会计核对格式，先手工开票过渡 |
| 对公转账到账确认依赖人工 | 上线"上传回单+人工核销"，后续自动化 |
| 正式域名注册/支付卡流程 | 提前办理，优先 Cloudflare/Namecheap 通道 |
| 自研工作量大、周期长 | 复用开源插件（发票/报表/搜索），聚焦差异化 |
