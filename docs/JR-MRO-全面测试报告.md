## 1. 本次核心修复：商品矩阵（列表页）图片不显示

### 1.1 现象
- 商品矩阵（列表页）部分产品图片不显示；商品单页能正常显示图片。
- 后台商品列表、前台分类页/首页网格同样受影响。

### 1.2 根因（已证实）
- 列表卡片组件使用 `base_image.small_image_url / medium_image_url`，即 ImageCache 缓存缩放图 URL：`/cache/{small|medium}/{path}`。
- 该类 URL 由 `packages/Webkul/ImageCache` 的 `ImageUrlBuilder` 生成，由 `ImageCacheController` 在**首次请求时**将原图缩放并写入 `storage/app/public/cache/`。
- 实测 `storage/app/public/cache/` 目录完全缺失 → 缩放图生成/读取失败 → HTTP 404 → 列表图不显示。
- 单页使用 `storage/app/public/product/{id}/` 原始图，目录存在，故单页正常。

### 1.3 修复
- 创建 `storage/app/public/cache/{small, medium, large}` 目录并赋予 `galaxy:www-data` + 777 权限。

### 1.4 验证
| 验证项 | 结果 |
|---|---|
| 单图三档缓存 URL（product/2） | small/medium/large 全部 HTTP 200 |
| 列表 API 图 URL（分类页抽样） | 24/24 = 200 |
| **全量缓存图 URL 并发验证** | **1204/1204 = 200，0 失败** |
| **全量搜图替换完成后复核** | **1206/1206 = 200，0 失败**（500 商品新图 + 测试商品 520，全部可达） |

### 4.1 附加发现并修复：`cache/data` 目录稳定性
- 回归中日志检出约 503 条今日 `production.ERROR`，根因：`storage/framework/cache/data` 的二级目录树（`xx/yy`）被 `cache:clear`（搜图替换任务的副作用）清空，高并发写缓存时窗口失败。
- **不影响功能**（页面均 200），但属日志噪声。
- **修复**：重建完整 `cache/data` 二级目录树（65536 个）+ chown galaxy:www-data + 777；随后触发 6 个请求，cache/data 错误新增 **0**，`55/d1`、`13/fd` 等目录自愈存在。
- **建议**：运行中避免频繁 `cache:clear`（会再次清空目录树）；如需清理缓存，先跑重建脚本再清。
